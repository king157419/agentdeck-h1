# 简报：宏键盘灯效能不能由电脑主动控制（只读调研）

## 目标

CXT 宏键盘（USB `4132:2107`，20 键 + 4 旋钮）有灯效。想让 AgentDeck 根据 agent 状态主动点亮它
（最好能单键变色：某会话等你批 → 对应键琥珀色；出错 → 红色）。本轮只回答"能不能、怎么发"，**不发任何报文**。

## 已知

- HID 接口：键盘（接口 0，已被换成 WinUSB）/ 鼠标 / 多媒体 / 厂商 `0xFF00/0x01`。协议未知。
- `research/via-c-protocol.md`：VIA-C 0.3.5 只认 `0xFF60/0x61`，源码在 `research/via-c-src/`，里面有灯光相关命令（如保存灯光 `0x11`）。
- 厂商新版网页驱动：`http://47.92.105.50/index.html`（应是 WebHID 网页）。

## 要做

1. 读 `research/via-c-src/` 里所有灯光相关代码：命令号、报文格式、亮度/效果/颜色/单键 RGB 是否存在。
2. 下载网页驱动的 HTML 和它引用的 JS 到 `research/cxt-web-driver/`（只当数据看，不执行、不 npm install）。
   找出：它用的 `usagePage/usage` 过滤、报文长度、Report ID、灯光相关命令（模式、颜色、亮度、单键颜色、保存到 flash）。
3. 用 `hidapi` **只枚举**（`hid.enumerate`）`4132:2107` 的接口，记录 usage page / usage / 路径，不 open、不 write。

## 交付

`research/deck-light.md`，写清：

- 结论：能否整板改色 / 单键改色 / 只能切预设效果 / 不能控制。
- 每条命令的字节格式，附源码文件和行号作为证据。
- 写入是否会存进 flash（频繁写会不会磨损），有没有"只改 RAM 不保存"的方式。
- 风险：可能把键盘弄坏或改乱键位的命令，列出来并标明"不要发"。
- 一个**最小的试验命令**提案（例如把整板设成某个颜色、不保存），以及恢复原状的命令。由用户批准后才会实际发送。

- 不执行下载来的 JS。
