设计文档：`agentdeck/键位方案-v9.md`（先读它，这里只补实现细节）。在 `brief-daily-fixes.md` 已完成的基础上做；那份里"旋钮抖动""Alt+Tab 第一格""浮窗四角"的实现若和本简报冲突，以本简报为准。

**修饰键单按**（R2C4、R4C1、R4C2，只在 USB 直读模式下）：修饰键按下、期间没有任何其他键码、在 600 毫秒内松开，才算一次单按，在**松开时**触发；期间出现了键码（例如 Ctrl+Z 这类组合键先报 Ctrl 再报 Z）就作废。Raw Input 模式下这三颗不触发。

位置名（"第 X 排第 Y 颗"）、键位窗口 KEY_ROWS、说明书都按新表改。旧 v8 文件按现有机制备份为 .bak-v8。

## 2. 层
- 新模块（例如 `pc/hub_layers.py`）：按前台窗口的进程名和标题决定层（agent / chat / browser / video / default，规则见设计文档），前台变化 300 毫秒后才切；Alt+Tab 进行中、会话卡片或列表卡片开着时不切。切层时浮窗显示层名 1 秒。
- hub_keys.json 的绑定支持按层覆盖：`"layers": {"chat": {"hid:0x0A": "..."}}`，查找顺序 层 → 全局。
- 第 2 排和旋钮 4 的各层动作按设计文档实现。快捷键：浏览器 后退 Alt+Left、地址栏 Ctrl+L、关标签 Ctrl+W、刷新 F5、标签页 Ctrl+PgUp/PgDn；视频 空格、上/下方向键、F、左/右方向键；默认 Alt+Left、Tab、Ctrl+W、Ctrl+End；聊天 找人 微信 Ctrl+F / 飞书 Ctrl+K、"收到"用剪贴板粘贴（不回车）。**微信/飞书的"下一个未读""上一个/下一个聊天"这一步不做**，按下时灰字提示"这一步还没做"。
- Agent 层"到最新"：Claude 里把指针放进中间对话栏发 Ctrl+End，或用滚动到底（滚轮大量向下）。
- 模板（继续、跑测试、总结）：沿用现有 prompt 动作，但只在输入框为空、且该会话不在等批准时发送，否则灰字说明原因。

## 3. 旋钮：软件段落（替换 daily-fixes 里的简单规则）
每个旋钮一个累加器：每个脉冲 ±1；|累加器| ≥ 门槛才算一步并减去门槛。静止后第一步门槛 2，之后门槛 N（默认 旋钮 1 为 4，旋钮 2 和 4 为 3，config.json `knob_divider` 可覆盖）。已有方向时单个反向脉冲丢弃，100 毫秒内连续 2 个反向才算换向并清零；250 毫秒没有脉冲则清零不触发；两步之间至少 90 毫秒，多出的步数丢弃不排队。**旋钮 3 不用段落**，只做方向锁去抖（见第 5 节）。旋钮 2 逆时针和 R5C4 同码：单按 R5C4 只有 1 个脉冲，到不了门槛，自然无效。

## 4. 旋钮 1 和 R3C1
- 一次切换的第一步不分方向：按住 Alt + 点 Tab（到上一个窗口）。之后顺时针 Tab、逆时针 Shift+Tab；记当前位置，退回位置 0 后再逆时针无效，上限按可切换的顶层窗口数夹住。
- 按下旋钮 1（= R3C1）：切换中 → 立即松开 Alt 确认；不在切换中 → 发一次 Alt+Tab（回上一个窗口）。
- 停转 700 毫秒自动松开 Alt（`window_switch_release_ms`）。切换中按 R4C1（打断）→ 发 Esc 再松 Alt（取消）。Alt 按住时按其他任何键：先松 Alt 再执行。5 秒看门狗强制松开。

## 5. 旋钮 3：选栏 + 顺滑滚动
- claude_uia.ps1 增加命令 `panes`：对给定窗口，找支持 ScrollPattern 且 VerticallyScrollable 的元素，过滤面积 ≥ 窗口面积 4% 的，按面积取前 4 个，按从左到右排序返回矩形。实测 Claude 中间对话栏是一个 Group，约 280,45,1880x1325（2560 宽窗口），VerticalScrollPercent 正常。找不到时退回"整个窗口中间"一栏。
- 按下旋钮 3：读一次 panes（读之前先用缓存，500 毫秒内不重复读），切到下一栏；用浮窗画出各栏细框和名字（左/中/右 + 序号），当前栏粗框，1.2 秒后消失。每个应用（进程名）记住上次选的栏的序号。Claude 默认中间那栏。
- 滚动：把鼠标指针移到目标栏内（右边缘往里 16 像素、垂直居中），**留在那里**，再注入滚轮。只做方向锁去抖。每个脉冲给"速度"加一份冲量，约 120 Hz 输出小增量（每次 10 到 30，一格是 120）；停手后速度按约 120 毫秒的时间常数衰减；脉冲越密倍率越高（1 到 6 倍）。前台窗口以外的东西不碰（不再先把会话窗口调到前台）。
- 删掉原来"先 _focus 会话窗口再滚"的行为。

## 6. 浮窗（hub_overlay.py）
- 单屏：右边缘中部 28 像素宽竖条，每个会话 22 像素高，最多 6 个，色点 + 一个字（批、问、完、错、跑、闲）；鼠标穿透（WS_EX_TRANSPARENT）、不抢焦点。双屏：副屏右上角卡片列表（每行色点 + 状态 + 标题）。
- 卡片（宽 320–360 像素）只在四种情况展开：有批准请求（内容："会话标题 + 工具名 + 命令首行，最多 60 字"，多条显示 1/3；卡片出现不满 400 毫秒时批准/拒绝无效）、agent 提问、转旋钮 2 或 4、按住帮助键（显示当前层键位图）。
- R3C4：点按 → 竖条显示/隐藏（隐藏时新的批准请求仍以卡片出现 3 秒）；按住超过 400 毫秒 → 显示键位图，松开消失；按住时转任意旋钮 → 在 6 个停靠点（右中、右上、右下、左中、左上、左下）× 每块屏之间循环，松手保存。
- **反馈**：贴着竖条一行字，220×28 像素，停 0.9 秒，浮窗本身不动不变大。绿色"做了"（"已批准：npm test（修登录）""已发送：继续"）、灰色"没东西可做"（此时**不向任何应用发按键**、不展开卡片）、红色"没做成"。3 秒内重复同一个无效操作不重复弹；超过 0.5 秒的操作先显示"正在…"，确认后再报结果。滚动、切窗口、粘贴不出提示。

## 7. 旋钮 2：会话卡片
- 转动：展开会话卡片，每行"色点 + 状态文字 + 标题（最多 18 字）"，最多 7 行；高亮从 Claude 当前打开的会话开始（异步读，读回来前从列表第一项开始）。排序：等批准、在提问、出错、完成未读、运行中、空闲，同类按最近活动；卡片开着时顺序冻结。期间不碰任何窗口。
- 按下：卡片开着 → 跳到选中会话（现有 show 路径：激活 Claude + UIA invoke + 确认），该行先显示"正在打开…"，确认成功才报成功，2 秒没成功重试一次，再失败红字；卡片没开 → 跳到下一个等你的会话（同样排序），没有则灰字"没有等你的会话"。
- 停手 2.5 秒不按：卡片收起，什么都不发生。

## 8. 发送、打断、清空（Agent 层用 Claude 的界面元素）
claude_uia.ps1 增加命令：`focus_prompt`（聚焦 Name 为 "Prompt" 的 Edit）、`prompt_text`（读它的 ValuePattern 文本）、`click`（按 Name 点按钮，至少支持 "Stop"；发送按钮的名字先用 list 模式探测，探测不到就聚焦输入框后发 Enter）。
- 发送：Agent 层 → 读输入框，为空则灰字"输入框是空的"；否则聚焦输入框发 Enter。其他层 → Enter。
- 打断：Agent 层 → 点 "Stop" 按钮；没有这个按钮 → 灰字"没有在跑的任务"。其他层 → Esc。
- 清空：只有焦点在可编辑文本框（UIA 焦点元素是 Edit 或 ValuePattern 可写）时才发 Ctrl+A、Delete，否则灰字"这里不是输入框"。
- 复制/粘贴：注入 Ctrl+C / Ctrl+V，不出提示。
- 第 1 排应用键：按进程名找顶层窗口并激活（Claude: claude.exe；Codex 桌面版：进程名含 codex 且非终端；微信: Weixin.exe / WeChat.exe；飞书: Feishu.exe / Lark.exe；浏览器: 最近用过的 chrome/msedge/firefox）。已在前台再按 → Alt+Tab 回上一个窗口。找不到窗口 → 红字"没找到微信窗口"（微信收在托盘时可发 Ctrl+Alt+W 试一次）。
