# 简报：界面第二版，换成网页渲染

## 为什么
第一版美化用户看了，觉得"有变化但不多，没达到要求"。根因是 Tkinter 的上限：没有抗锯齿圆角、阴影、像样的字体排版，做不出 Linear / 苹果备忘录那种干净。
所以改成 **pywebview + Edge WebView2**（Win11 自带）渲染 HTML/CSS，Python 逻辑不变。

设计原则（用户原话）：
> 像 Linear 的官网或者苹果备忘录一样干净：目标简单、架构简单、设计简单、实现简单。砍掉标语、提示文字和次要标签。如果一个页面非得靠这些东西才看得懂，那就去改布局。每个决定都要同时提升 UX、DX、AX，而且不能弄坏任何东西。

## 架构
- 新建 `pc/ui/`：`overlay.html`、`app.html`、一份共用 `style.css`、少量原生 JS（不用框架、不走 CDN，全部本地文件，PyInstaller 打包进去）。
- `pc/hub_overlay_web.py`：和现有 `Overlay` 对外接口完全一致（hub 调的方法、`run(on_ready=...)`、hidden 等），内部用 pywebview。状态变化时 Python 把 state JSON 推给页面；页面按钮通过 js_api 回调现有的 action。
- WebView2 不可用时自动退回现有 Tk `Overlay`，写日志。
- `agentdeck_app.py` 用 `ui_factory` 选新浮窗；首次引导、键位、诊断合并成**一个**主窗口 `app.html`，左侧三项：会话 / 键位 / 设置（设置里放全局启用、开机自启、诊断结果、日志文件夹）。系统托盘菜单保持原生。
- 依赖：pywebview（固定版本，写进 requirements 或 build 脚本），改 `agentdeck.spec` 把 `pc/ui/` 打进去。

## 视觉规格
- 字体：`"Segoe UI Variable", "Microsoft YaHei UI", sans-serif`，正文 13px；命令用 `"Cascadia Mono", Consolas` 12px。
- 颜色跟随系统深浅色。深色：底 #0E0F11，面板 #16171A，分隔 rgba(255,255,255,.06)，正文 #E8E8EA，弱文字 #8A8F98。浅色反过来。状态色沿用：运行 #48B879、待批 #E5AD46、完成 #609CE3、出错 #ED6969、空闲 #6B7079。
- 浮窗：无边框、12px 圆角、1px 细边、柔和阴影、置顶、**不抢焦点**（WS_EX_NOACTIVATE）、可拖动、记住位置。
  - 每个会话一行，行高 32px：6px 状态点、名字、右侧弱色的已运行时长。
  - 待批的那行左侧 2px 琥珀竖线。
  - 待批卡片：命令放在等宽代码块里；风险只在高 / 危急时显示一个小色块标签，"再按一次"这类安全提示必须保留。
  - 两个按钮：批准（实心）、拒绝（描边），按钮上用小号弱色字标出对应的物理键位。
  - 没有会话时浮窗收成一个小胶囊，只显示状态点。
- 主窗口：820×560，无多余标题和说明文字；键位页画出 4×5 键帽 + 4 旋钮的真实布局，每颗键上写功能。
- 不加装饰性动画；只允许 120ms 以内的颜色 / 透明度过渡。

## 硬约束
- 不改 hub、按键、安全逻辑；不打开 COM4、不碰 USB 键盘、不启动真实 hub（截图用假数据）。
- 不读写真实 `~/.claude`、`~/.codex`。不 git commit。可以打包 exe 验证能启动，但打包前确认没有 AgentDeck.exe 在跑。
- 测试断言旧 Tk 文案的，保留 Tk 退回路径的测试；新浮窗另写测试（state → 页面数据的转换、js_api 回调转发到 action）。
