# AgentDeck 竞品交互拆解 · 2026-11-22

对照 [键位方案 v9][51]，按从开机到引用追问的顺序记录公开文档能确认的操作。核心差异在于按钮接的是通用快捷键、终端输入，还是 agent 的会话与请求。有三种值得直接借鉴的动作：近期会话直达后聚焦输入框、停止后召回但等用户发送、选段后带引用进入追问。后两种已有原生软件入口，可先验证桌面端再映射。[01][12][24][34][46][51]

## 总表

- **✔** 有明确入口。**✘ 没做**指该产品或配置的公开动作范围里没有原生入口。**? 没查到**表示资料不足，括号或分号后也会指出只确认了部分步骤。来源编号在每行产品名后，适用于该行各格。
- 难点格子中的「→ 键鼠／手机／语音」表示退路。可在宿主输入框重输、调用原生快捷键、另开会话或选段复制。通用语音和快捷键依赖宿主提供相应功能。
- 第 3 步的 ✔ 说明可以选会话，只有明确写出输入焦点时才确认落点。第 8 步的 ✔ 说明有可核实的审批或可见控件操作，各产品覆盖的工具与请求类型不同。Claude CLI 的 computer use 文档另列了逐应用批准和 macOS 系统权限，不能据普通工具审批推定插件或手机能完成所有这些提示。[09][10][22][24][48][50]
- 第 9 步看停止与召回的组合。第 10 步区分进入当前轮的插话和下一轮的排队。第 11 步要求主任务继续，并能借用当前会话上下文。第 12 步看是否将一个选段带入追问，手动复制属于退路。

## 难点四步

### 9 · 停止、召回、修改、重发

- **Codex CLI** 有完整链路。运行中 Esc 停止，到空输入框用 ↑ 找回上一条草稿，改完或直接 Enter 发。Ctrl+R 可搜索更早的提示。空框双 Esc 是另一个动作，编辑历史里的用户消息并从该点分叉。Claude Code CLI 同样可 Esc 停止、↑ 召回，但有排队消息时 ↑ 会先取回队列，双 Esc 还会随草稿是否为空而变化。[23][46][47]
- **Codex 桌面版** 两个平台的命令表都有空框 ↑。已发消息的 Edit 有主会话用户报告旁证。**Elgato Claude Shortcut Profile** 把历史和滚动各放在一个旋钮，双 Esc 是宿主回退。**agentsd** 和 **VibeDeck** 只贡献停的那一半，前者发 Ctrl+C 给前台 Ghostty，后者三击会话键停止当前轮。[07][09][24][29][45]
- **首选学习 Codex 的空框召回。** 把历史动作和回退动作分开。重发只需要用户再按现有发送键。用量用尽时，这条链路保住原稿，什么时候能跑取决于宿主恢复可用。

### 10 · 排队与立即插话

- **Codex CLI** 工作中 Tab 排队、Enter 插入当前轮。**Codex 桌面版** 的 Follow-up behavior 可设 Queue 或 Steer。**Codex Micro** 官方演示给出了硬件跟进排队；独立的硬件 Steer 默认入口没查到。[01][03][25][26][46]
- **Claude Code CLI** 工作中可先排队，Ctrl+Enter 或 Ctrl+X Ctrl+S 提前发送。**Remote Control** 可在手机继续引导，手机端队列快捷键没查到。**Happy** 接支持的 Happy Harness 时，在同一框发消息可以 mid-turn steer Claude Code/Codex CLI；其某些其它 harness 会先中断再接着执行。**Antigravity App** 暴露队列的 Send now、Edit、Delete，Voice mode 还可当场口头纠偏。Antigravity CLI 的 Alt+M 是 CLI 自己的覆盖默认行为键。[21–23][32][33][49]
- **首选学习 Codex 的两种发送语义，加上 Antigravity 的可见队列。** 同一个草稿可以有两种投递方式。明确标出「下一轮」和「立即插话」，避免切回来时才发现草稿已按另一种方式投递。

### 11 · 主任务继续时旁问

- **Claude Code CLI** 用 `/btw 问题` 弹出独立回答，主任务继续。**Codex CLI** 用 `/side` 或直接附问题，副对话和主 transcript 分开，TUI 仍可看主任务状态。**Codex 桌面版** 有直接开 Side chat 的快捷键。Claude Remote Control 网页可从菜单或历史消息 Fork，原会话继续，但 Fork 是可继续执行的新会话。[22–24][46]
- **首选学习 Claude /btw 的轻量入口，并用 Codex Side chat 承担可能有多轮的追问。** Antigravity Voice mode 能回答进度和前文小问，公开文档没查到独立副对话，因此不计作完整旁问。Manager 的 Playground 已有退役记录。[31–33]

### 12 · 引用回复的一段追问

- **Antigravity App** 先选回复文字，再点 Quote 或 Windows Ctrl+L/Ctrl+I，macOS Cmd+L/Cmd+I。选段以可见的引用卡进入输入框。**Codex Remote 手机** 的选段菜单可 Ask in side chat，把选段用作副对话起始上下文。**Codex CLI** 有选段/复制路径以及整条最新回复的复制键，公开资料没查到直接把选段变成引用的动作，比较稳妥的退路是复制后贴入 composer。[28][34][46][47]
- **首选学习 Antigravity 的引用卡。** 同一个选段应能在输入框里核对、移除，然后选择发到主会话或发成旁问。Homerow/Hunt-and-Peck 适合启发如何点到「引用」按钮。跨应用精确选中文字需要另设入口。[34][43][44]

## Codex CLI 与桌面版专项核对

本文桌面版包括合并到新版 ChatGPT 桌面应用后的 Codex 视图。Windows/macOS 命令表现已使用这一名称。旧安装和绑定可能不同。[24][27]

| 要核实的事实 | Codex CLI | Codex 桌面版 |
|---|---|---|
| 召回上一条 | ↑/↓ 浏览草稿历史，Ctrl+R 搜索。[46] | Windows/macOS 空 composer 按 ↑。先聚焦输入框。[24] |
| 打断 | TUI 源码的活动轮打断默认用 Esc，空 composer 的双 Esc 回溯另算。Ctrl+C/exit 在官方交互命令说明里可用于退出，不用作跨客户端的统一停止键。[46][47] | 桌面端可从运行中的会话操作停止，具体控件位置随版本。公开快捷键表明确将 Esc 用于拒绝打开的审批请求，没查到可跨版本依赖的桌面 Stop 全局快捷键。[24][26] |
| 干活时排队和插话 | Tab 排下一轮，Enter 送进当前轮。[46] | Settings → Follow-up behavior 设 Queue 或 Steer，再用 composer 发送。Queue 等当前轮结束，Steer 导向当前工作。桌面更新日志也有立即 steer 的记录。没查到在 Windows/macOS 都一致的每次切换快捷键。[25][26][28] |
| 旁问 | /side 或 /side 加问题。默认临时；本地 fullscreen 且启用 tui_workspace、有已存历史时可重开。[46] | Windows Ctrl+Alt+S，macOS Cmd+Option+S。桌面命令表确认打开 Side chat。[24] |
| 编辑上一条重发 | 空框双 Esc 进入历史消息编辑并分叉；若只想复用原文，↑ 召回后改稿或原样 Enter，新发一轮。[46] | 空框 ↑ 回填上一稿，直接改稿并发送。主会话已有消息的 Edit 有用户报告旁证；没查到足以确认各版本提交后覆盖或分叉语义的官方说明。排队项是另一类消息，不用它推定已发历史的行为。[24][26][29] |

## 定位归类

每项先列厂商或项目自己的短句，再给基于公开交互的判断。这里的「替代」可以只覆盖点选、滚动或听写环节。

### 替代键鼠

- **Talon + Cursorless** “Powerful hands-free input” — Talon 以语音及声音替代通用输入，Cursorless 解决编辑器里如何精确指定代码。[38][39]
- **Windows Voice Access** “control their PC and author text using only their voice” — 通用导航、点选和输入都可用语音完成。[40][41]
- **Wispr Flow Command Mode** “rewrite selected text, draft new text, or search the web” — 替代文字编写和修改，仍需要可用的选区或输入焦点。[42]
- **Homerow** “Click anywhere, without a mouse” — 用键盘标签替代鼠标点击和滚动。[43]
- **Hunt-and-Peck** “Simple vimium/vimperator style navigation for Windows applications” — 用 Windows UI Automation 标签替代受支持控件的鼠标点击。[44]

### 给键鼠加速

- **Codex Micro** “Your command center for Codex chats” — 把会话、状态、听写和审批放到桌面触手可及的位置。[01–03]
- **Logitech MX Keypad · Claude Code / Codex** “The Customizable Multi-App AI Control Center” — 以每应用配置和插件把高频操作搬到 LCD 键。[04–06]
- **Stream Deck · Elgato Claude 配置** “Control Claude with Stream Deck for faster workflows” — 用预置快捷键、模板和旋钮减少终端及桌面操作。[07][08]
- **Stream Deck · agentsd** “Stream Deck plugin for managing Claude Code sessions” — 在硬件上切换插件目标、读状态、处理 hook 审批。[09]
- **Stream Deck · Claude Code Approver** “brings Claude Code's permission prompts to your Stream Deck” — 专做免切回终端的提示审批与观察。[10]
- **优篮子 AU05** “Press to Talk. Type Less.” — 语音键麦加通用快捷键，配合宿主做日常控制。[13]
- **D200 系列 + puritysb/AgentDeck** “Local dashboards and physical controls for AI coding agents” — 把会话和操作搬到外置 LCD 键。[14–16]
- **claude-desktop-buddy** “desk pet on ESP32” — 把近期回复、等待和批准/拒绝搬到手边。[17]
- **Keychron F4 HE** “a four-key controller for working with AI” — 用四个实体键缩短发送、语音和评审操作。[18]
- **Codex 桌面版** “Chat, Work, and Codex” — Codex 视图把多会话和待关注工作做成桌面控制面。[24][27]
- **Antigravity Agent Manager／App** “a second surface that stripped away much of the ‘IDE’ UI” — 让管理会话成为可独立操作的界面。[30][31]
- **Claude Squad** “Run multiple AI coding agents in parallel” — 用 TUI 选中并接管多个终端会话。[35]
- **cmux** “vertical tabs and notifications for AI coding agents” — 提供跨工作区导航和通知定位。[36]

- **Stream Deck · VibeDeck** “Every coding agent on one Stream Deck” — 以会话键聚焦、语音和审批，作为桌面操作补充。[45]
- **Codex CLI** “fast, keyboard-first control over Codex” — 在终端中把历史、队列和旁问收进按键与命令。[46][47]

### 离开电脑也能管

- **VibeKeys Max** “drive Claude Code or OpenAI Codex with voice input and physical controls” — 蓝牙模式加速桌面，Remote 模式可带着设备离开电脑继续选会话、读和发。[11][12]

- **Claude Code Remote Control** “Continue a local Claude Code session from your phone, tablet, or any browser” — 保留本机执行，换手机或浏览器继续管。[22]

## 对 AgentDeck v9 的建议

1. **旋钮 2 按下完成「会话切换 → 输入框聚焦」。** 学 Codex Micro 的近期/优先分组和 Windows Voice Access 的两段目标定位。转动仍只动浮窗，按下后用会话标识确认命中再定位输入框。有审批或找不到输入框时留在当前安全界面并反馈。这样接下来按语音键就有明确的文本落点。[01][24][40][51]
2. **用 Agent 层第 2 排第 1 键的长按召回上一条。** 学 Codex 空框 ↑，保留短按「继续」。停止继续用第 4 排第 1 键。召回只回填，保留第 4 排第 3 键确认发送。将编辑历史分叉留给宿主界面，避免恢复原稿时跳到另一条分支。[23][24][46][51]
3. **第 4 排第 3 键短按按常规发送，忙时用长按请求立即插话。** 学 Codex Queue/Steer 和 Antigravity 队列卡。浮窗在发送前后显示明确的投递方式，仅在已确认宿主支持时执行长按路径。这样语音附加测试与紧急纠偏各有可预测的动作。[25][32][46][51]
4. **把「旁问」放在 Agent 层第 2 排第 3 键的长按。** 学桌面 Codex 的 Side chat 和 Claude CLI 的 /btw。保持短按「总结」，长按先打开宿主已核实的旁问入口再接语音。Claude 桌面端入口没核实前，可显示不可用并保留主任务上下文。[23][24][46][51]
5. **新增「引用所选」作为 Agent 层复制键的长按。** 学 Antigravity Quote 送入输入框的可见引用卡。无选区时显示「没东西可做」。点选模式用两位标签定位会话区域和引用按钮，选段范围由宿主选区或后续支持的文本定位动作负责。这样用户可以先核对片段，再说追问。[34][43][44][51]
6. **用同一优先级喂给浮窗和旋钮 2 按下的「下一个等你」。** 学 Codex Micro 的 Priority chats 与 cmux 的最近未读跳转，将待批准、待回答和未读完成显式标记。用户从微信或视频回来，只需一次确认即可定位等待会话。[01][24][36][51]
7. **固定批准/拒绝键显示会话、请求和目标。** 学 Claude Code Approver 将工具名放在键上，及 Hardware Buddy 在审批画面才改变按键语义。能定位具体请求时才启用固定键。遇到 computer use 的新应用授权、系统权限或目标信息不全时，直接聚焦原生提示供用户查看。这样一对红绿键可沿用，区分清楚哪次操作在被批准。[10][17][50][51]
8. **冷启动保留登录自启动路径，并在浮窗给出「已连接／等待设备」。** 学 Voice Access 将启动入口放在登录设置中，以及 D200 插件记录启动端点和重连状态的做法。以键盘任意时点插入后能继续工作为验收条件。第一次安装和日常开机可以各有一条明确路径。[15][41][51]
