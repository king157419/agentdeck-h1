# Agent 状态屏：产品调研（附带"产品经理在干什么"的旁注）

日期：2026-11-08（北京时间）

每节末尾的「PM 旁注」解释这一步产品经理在想什么、为什么这么做。正文是调研内容本身。

---

## 1. 需求：真正的痛点是"Agent 停下来等你，你却不知道"，而不是"想看它在干嘛"

**我听到的需求**：一个桌面小屏，显示 Agent（Claude Code、Codex 这类）的运行状态。

**拆开后，用户其实想要三件事，重要程度从高到低：**

| 层次（借用 Kano 模型） | 用户期望 | 做不到会怎样 |
|---|---|---|
| 基本型：必须有 | Agent 卡在"等你确认 / 等你回答"时，**一定**提醒到我；也不要乱报 | 做不到这一点，产品就没用 |
| 期望型：越好越满意 | 一眼看出它在思考、在跑工具、跑完了还是出错了；同时开好几个会话也分得清 | 用户会觉得"还行，但不如手机通知" |
| 兴奋型：意外惊喜 | 有性格的桌宠表情、用量/额度表、声音、摸一下就有反应 | 没有不扣分，有了会想晒小红书 |

**证据（不是我猜的）：**
- Claude Code 的 GitHub 上有人专门提需求"等用户输入时给个通知"（issue 36885，2026-03），说现有办法只能在每次调用工具时都响，太吵。这正好是"基本型"痛点。
- 已经有现成的软件专门做这件事（agent-notifications，支持 Claude/Codex/Cursor 等 7 家），说明需求是真的，有人愿意为它写代码。
- Anthropic 自己的研究：Claude Code 一轮的中位数时长约 45 秒，但用户越熟练，放手让它连续跑的时间越长。跑得越久，人越会走开，"它停下来我不知道"的损失越大。

**用户是谁**：每天用 Coding Agent 干活的程序员，尤其是同时开多个会话、会离开屏幕的人；其次是喜欢桌搭、愿意为好玩花钱的人（小红书主力人群）。

> **PM 旁注**：第一步不是想"屏幕上画什么"，而是问"用户不买这个会损失什么"。答案是"白等 Agent"——这个损失越具体，产品越好卖。把需求按"必须有 / 越多越好 / 惊喜"分层，是为了以后砍功能时知道先砍哪个。

## 2. 消费：这个品类没有公开销量数据，现有信号指向"几十到一两百元的一次性配件"

**先说实话**：我没找到"Agent 状态屏"这个品类的任何销量或营收数据，它太新了。下面全是间接信号，每条标了是事实还是推断。

| 信号 | 说明了什么 | 类型 |
|---|---|---|
| Clawdmeter（ESP32 屏显示 Claude Code 用量和状态）在 GitHub 有 2.3k 星、408 个复刻 | 愿意**自己动手做**的人不少 | 事实 |
| 小米 HachimoDock 定位"自制成本约 150 元" | 大厂判断这个价位是普通人愿意试的门槛 | 事实（定价逻辑是推断） |
| 用户已经在为 Agent 付 20～200 美元/月 的订阅 | 他们对"让 Agent 更好用"的配件有付费习惯 | 推断 |
| 高端 Agent 硬件（如 Violoop，约 399 美元）还在众筹、没出货 | 贵的硬件还没被市场证明 | 事实 |
| 你发的那条小红书（Glance 小屏）：574 赞、376 收藏、98 条评论；能看到的评论里一大半是"求详情 / 蹲介绍 / 私我"，有人问有没有英文版、能不能盯服务器 | 收藏数接近点赞数的 2/3，说明很多人想"留着以后买或做"，不只是随手点赞；而且作者已经在用小红书众筹真卖了 | 事实（"想买"是推断） |

**结论（推断，没验证）**：如果卖成品，合理价位在 **50～150 元**；更可能的商业形态是"开源 + 卖套件 / 卖外壳"，而不是卖整机。

**怎么低成本验证（下一步可以做）**：
1. 去你发的那条小红书看评论区，数有多少人问"链接""怎么做""能卖吗"。
2. 闲鱼、淘宝搜"Claude 状态灯 / AI 桌宠 / 编程助手屏"，看有没有人在卖、卖多少钱、有没有成交。
3. 自己做好后发一条小红书，看收藏和"求教程"的比例。

> **PM 旁注**：产品经理最常犯的错是把"我觉得会有人买"当成事实。这一节刻意把事实和推断分开标。没有数据时，不要编数据，而是设计一个最便宜的实验去拿数据。

## 3. 竞品：最大的竞争对手是免费的系统通知，不是别的硬件

| 竞品 | 形态 | 价格 | 强项 | 弱项 |
|---|---|---|---|---|
| **系统通知 / 声音提醒**（Claude Code 钩子、agent-notifications） | 纯软件 | 免费 | 零成本、5 分钟配好 | 会被淹没在一堆通知里；人离开电脑就看不到 |
| **Clawdmeter**（GitHub 开源） | ESP32-S3 带圆形 AMOLED 屏的现成开发板 | 板子一两百元 | 用量表 + Clawd 小人表情 + 等待提醒；板上按键能当键盘按"确认" | 只支持 Claude；要买指定的屏幕板 |
| **Claude Notifier**（element14 社区 DIY 作品） | ESP32-S3 触屏 + 舵机敲**真的铃铛** | DIY | 物理铃铛非常抓注意力；通过局域网 HTTP 接收状态，不用装软件 | 一次性作品，不能买 |
| **小米 HachimoDock**（2026-10-26 刚开源） | 复古游戏机外形，屏 + 按键 + 摇杆 + 语音 | 自制约 150 元 | 能**语音派任务**给 Codex 等，显示思考/执行/等待确认；桌宠可换形象；能连小米智能家居 | 功能多、做起来复杂；状态显示只是它的一个功能 |
| **Glance 小屏**（你发的那条） | 天气小电视改的方形彩屏，夹显示器下沿 | 小红书众筹中 | 不打扰、一眼看懂；能盯远程服务器 | 公司电脑不让接外设就用不了 |

**Glance 小屏细节**（作者"三百万"，帖子约 11-05 发）：硬件直接借用现成的"天气小电视"，作者自己重写固件。没有按键；屏上大字"your turn."提示该你回来了，下面写任务名，角上显示已经跑了多久；另有一页显示电脑 CPU 和内存。Wi-Fi 下走 MQTT、HTTP 兜底，也支持蓝牙和 USB 串口，数据加密传输；能盯 SSH 远程主机上的 Agent；界面支持十几种语言。正在小红书众筹，作者说"周末就发货"，价格帖子里没写。评论里有人说公司电脑不让接外设，作者回答不连电脑也能当时钟用。

> **PM 旁注**：Glance 证明了两件事——①"现成硬件 + 自己写固件"就能卖，不用从 PCB 做起；②小红书本身就是验证需求和卖货的渠道。这对你最有参考价值。

**空白在哪（机会点）：**
1. **最便宜、最简单**：别人都用彩屏开发板，一块 MAX7219 点阵 + ESP32 成本 30 元以内，插上 USB 就能用，不用配 Wi-Fi。
2. **同时盯多个 Agent**：Claude、Codex 一起跑的人，一块屏分区显示，竞品基本只盯一家。
3. **和你的灵宠合体**：灵宠本来就是"有性格的陪伴硬件"，8×8 表情帧库已经写好。"它替你盯着 Agent，Agent 等你时它会着急"——这个故事是别人没有的。

> **PM 旁注**：看竞品不只看"长得像的"，更要看"用户不用你时会用什么"——这里是免费的系统通知。你的产品必须回答：为什么比免费的通知更值得买？答案可能是"物理存在感"（离开电脑也看得到、铃铛会响）和"情感"（桌宠）。

## 4. 资源：手头的东西够做第一版，一个关键模块已经跑通

### 硬件（亲眼确认过的打勾）

| 东西 | 实际情况 | 能干什么 |
|---|---|---|
| ✅ ESP32 开发板（Type-C，CH340 串口芯片） | 经典 ESP32（D0WD-V3），双核、Wi-Fi + 蓝牙、4MB 闪存。原来跑着一个"蓝牙智能开关"程序，已整片备份 | 第一版主控 |
| ✅ MAX7219 点阵模块 | **是 8×8，不是 9×9**；红色单色，5 根线就能接 | 第一版的"脸" |
| ✅ LCD1602 字符屏 | 并口版，**背面没有 I2C 转接板**，直接接要占 6 根以上数据线，还要一个电位器调对比度 | 能显示 2 行×16 个字母（不能显示中文）。建议花 3 元买个 PCF8574 I2C 转接板焊上，就只要 4 根线 |
| 树莓派 5、树莓派 4B（带 SD 卡） | 你说有，没现场看 | 想做"带彩屏 + 语音"的高配版时用；第一版用不上 |
| 灵宠清单里 6 月的快递 | 主控 ESP32-S3 N16R8、两个 INMP441 麦克风、MAX98357A 功放、喇叭、WS2812 8×8 彩色灯板等；**不知道哪些没取** | 去驿站或淘宝"我的订单"查物流 |

### 软件和代码
- 灵宠仓库（D:/desk/lingchong）里已经有 5 种表情的 8×8 帧库（idle、sleepy 等），正好对得上这块点阵，可以直接复用。
- claudex/25 里有小智语音服务端，以后做"语音版"可以接。

### 人
- 你：会写代码、会用 AI，硬件是新手。
- 我：能写固件、烧录、看串口日志、调研、出接线图和外壳模型。看不到实物（见主汇报的分工表）。

> **PM 旁注**：盘资源是为了回答"用现有的东西最快能做到哪一步"。这一盘发现了两个关键事实：点阵是 8×8（设计要按 8×8 来）、1602 缺转接板（要么多接线，要么花 3 元）。这些细节如果到写代码时才发现，就是返工。

## 5. 硬件项目一般怎么走：不是"软件调通再移植"，而是"尽早上板子，软硬交替"

你想的"先软件调通，再移植到硬件"，对**显示内容和交互逻辑**是对的（可以先在网页里模拟点阵），但对硬件本身不对：接线错没错、屏幕亮度够不够、USB 会不会让板子复位，这些只有上了板子才知道。今天就踩到一个：PowerShell 写文件带了一个看不见的文件头，板子直接报语法错误——模拟器里不会出现。

| 阶段 | 业余做法 | 正式说法 | 本项目现在在哪 |
|---|---|---|---|
| 1. 定义 | 想清楚给谁用、解决什么、不做什么 | 需求文档 | 本文 |
| 2. 打通最小链路 | 开发板 + 杜邦线，证明"电脑→板子→屏幕"能通 | 原型 / 概念验证 | **电脑→板子已通，差接屏** |
| 3. 功能做全 | 接上 Claude Code 钩子、多状态动画、多会话 | 工程样机（EVT） | 下一步 |
| 4. 外形 | 3D 打印外壳、把线藏起来 | 设计样机（DVT） | — |
| 5. 固化 | 洞洞板焊死，或画 PCB 在嘉立创打样（5 片几十元） | 量产前验证（PVT） | — |
| 6. 给别人用 | 写教程、开源、或做 10 套小批量 | 量产 | — |

> **PM 旁注**：硬件的核心原则是"越晚发现问题越贵"：杜邦线阶段改一根线 1 分钟，PCB 打样后改要等一周、花几十元，开模后改要几万。所以每个阶段只回答一个问题，答完再往下走。
