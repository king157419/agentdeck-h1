# AgentDeck（暂名，中文候选"点将台"）· 投资人一页纸

**一句话：跨所有 agent 的 Codex Micro，外加高危操作的物理二次确认。** 一块桌面控制器 + 一个跨多家 agent 的控制软件，让开发者用按键指挥电脑上所有 AI coding agent。　　　2026-11 · 天使轮

**问题。** 重度开发者同时开 3–10 个 agent（Claude Code、Codex、Cursor、Qwen Code……），瓶颈变成了人：不知道谁在等自己（Claude Code issue #13024 获 81+ 反应）；宏键盘靠往前台窗口模拟按键，焦点一跑就批错窗口；auto mode 接手日常命令后，真正需要人把关的是 `git push --force`、生产 `kubectl`、数据库写入这类不可逆操作。

**方案。** 3.5 寸长条屏 6 等分对齐 6 个 RGB 机械会话键，下面是 ✓ / ✗ / 按住说话大键、Ctrl、截图键，右侧金属滚轮，USB-C。✓ / ✗ 走 agent 官方 `PermissionRequest` 钩子直接返回 allow / deny，不模拟按键；高危命令按两次，极危命令设备上不能放行；出错一律退回原生提示。控制软件免费：Stream Deck、优篮子 D200 和普通宏键盘把按键映射成 F13–F24 热键即可发批准 / 拒绝等动作，状态先在电脑置顶小浮窗里看（往它们按键屏推状态的原生插件还没开发）。全部本地运行。

**目前做到的（只列已验证的）**
- 本地中枢用真实进程端到端跑通：转发脚本 → 中枢 → 按键动作 → 钩子返回（转发进程喂 Codex 格式事件，还不是真实 agent 会话）。低危单击放行；`git push --force` 第一次只回"再按一次"、第二次放行；拒绝返回 deny；`curl | sh` 533 ms 退回终端确认，按 ✓ 返回 locked；中枢离线时退回原生提示。
- 不用我们硬件也能用（中枢 v1.3）：F13–F24 全局热键 + 置顶 6 槽小浮窗。用系统按键实测 F19 批准返回 allow、F20 拒绝返回 deny，浮窗正确显示会话状态和红色高危命令。
- 高危闸门（中枢 v1.4，`PreToolUse`）：两次 ✓ 返回 `{}`（agent 规则照常生效），✗ 或超时 deny；用真实进程和真实系统热键验证；演示模式已用真实热键 4 倍速跑通。**真实 auto mode 会话待测。**
- 离线测试：中枢 264 项单元测试（`test_hub*.py`，含演示模式与虚拟 v2 设备窗口）+ 回放自检 12/12，全部通过，含历史回归。
- 原型键盘隔离：宏键盘接口改走 WinUSB 直读，按键不再漏到其他窗口；组合键回放 10/10。
- **尚未验证 / 尚未开发**：真实 Claude Code / Codex 会话中连续使用；物理键 → 中枢；高危闸门在真实 auto mode 会话里的表现（闸门本身 v1.4 已实现）；设备回报的随机数校验（未开发）；Stream Deck / D200 按键屏原生插件（未开发）；v2 长条屏样机（未做，现有实体屏是 1602 字符屏）；国产 agent；macOS；工厂报价；外部用户。
