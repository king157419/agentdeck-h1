## 一、V2EX 版（节点：分享创造）

**标题：** 招 30 个"同时开 3 个以上 AI agent"的重度用户，免费试一个用按键指挥所有 agent 的工具（用你手上的 Stream Deck / 宏键盘就行）

**正文：**

先说明：这是我们自己在做的产品，发这帖是为了找人试用和挨骂，不卖东西。

**我们在解决什么问题**

我自己每天同时开 Claude Code、Codex，加上一两个国产 CLI。最烦的两件事：

1. 不知道哪个会话卡在权限提示上，经常一个 agent 干等了十几分钟我才发现。Claude Code 的 issue #13024（"需要知道什么时候该我输入"）有 80 多个人点了 +1。
2. 用宏键盘 / Stream Deck 批准，本质是往前台窗口模拟回车。焦点一跑，回车就打进了别的地方。

**我们做了什么**

一个本地中枢（hub），接各家 agent 官方的钩子（Claude Code 和 Codex 的 `PermissionRequest`）：

- 哪个会话在等你，电脑右下角的置顶小浮窗直接显示（Stream Deck / D200 按键屏原生插件还在做）；把设备按键映射成 F13–F24，按一下跳到那个窗口；
- ✓ / ✗ 不模拟按键，是中枢直接把 allow / deny 返回给发请求的那个会话，焦点在哪都不影响；
- `git push --force` 这类高危命令要按两次；`curl ... | sh` 这类设备上不让放行，退回终端自己确认；
- 中枢挂了、设备拔了，agent 回到自己原生的提示，不会默认放行。

**现在到哪一步了（实话）**

- 已验证：上面这条链路用真实进程跑通了（用 Codex 格式的钩子事件）；F13–F24 热键和置顶浮窗也用系统按键验证过；离线测试 100 多项通过。
- 没验证：在真实 Claude Code / Codex 会话里天天用。这正是要找你们的原因。
- 国产 agent（Qwen Code、CodeBuddy、Kimi、Trae）官方都有钩子，能不能直接批准还要实测，暂时只承诺状态显示。
- 第一批先支持 Windows，macOS 版在做。
- 我们也在设计一个专用硬件（长条状态屏 + 6 个会话键 + ✓/✗/按住说话），但**这次试用不用买任何东西**，用你手上的 Stream Deck、优篮子 D200 或普通宏键盘就行（按键映射成 F13–F24；状态先在电脑置顶浮窗里看，设备按键屏原生插件还没做）。

**想找什么样的人**

- 每天同时开 3 个以上 agent 会话；
- 能连续用 14 天，并开启匿名按键计数（只统计次数和耗时，不传命令、路径、项目名，本地可以随时查看要上传的内容）；

**隐私**

全部本地运行，中枢只监听 127.0.0.1，默认不联网，命令和代码不出本机。

**安装时要你自己做的两步**

- Codex 新装的钩子要你在 Codex 里输入 `/hooks` 手动信任，不信任就不会运行（这是 Codex 的安全设计，我们不会、也不能绕过）；

## 四、Reddit r/ClaudeCode（English）

> 发帖前先看一遍 r/ClaudeCode 当前的版规（是否允许自荐、是否要用特定 flair），按版规调整。不要用小号互顶。

**Title:** [Disclosure: our own project] Looking for ~30 people who run 3+ Claude Code / Codex sessions at once to test a hook-based approval controller (free, uses hardware you already own)

**Body:**

Up front: this is a product we're building. I'm posting to find testers and get criticism, not to sell anything. Nothing to buy in this test.

**The problem we're working on**

When I have several Claude Code and Codex sessions going, the slow part is me: noticing which one is blocked on a permission prompt, finding the window, and not fat-fingering Enter into the wrong one. Issue #13024 ("know when input is needed") on the claude-code repo has 80+ reactions, so I don't think it's just me.

Most macro pads and Stream Deck setups approve by sending a keystroke to whatever window has focus. That's the part we wanted to get rid of.

**What we built**

A small local hub that sits behind Claude Code's and Codex's official `PermissionRequest` hook:

- the hub tracks each session's state and shows who's waiting
- a key press jumps to that session's window (Windows today)
- ✓ / ✗ make the hub return `allow` / `deny` to the session that asked, no keystroke injection
- commands like `git push --force` need a second press
- things like `curl … | sh` or `-EncodedCommand` can't be approved from the device; they fall back to the terminal's native prompt
- if the hub isn't running or nobody presses within the timeout, you get the normal Claude Code prompt. A device "allow" also doesn't override your own deny rules.

**What's verified and what isn't**

- Verified: the relay → hub → key action → hook response path, end-to-end with real processes (using Codex-format hook events). Double-press for high-risk, locking for critical, and hub-offline fallback all checked. F13–F24 hotkeys and the always-on-top overlay were checked with real system keystrokes. 100+ offline tests pass.
- Not verified: daily use in live sessions. That's the point of this test.
- Windows first. macOS hub is in progress.
- Not built yet: native plugins that push status onto Stream Deck / D200 key screens. For now you map keys to F13–F24 and watch the overlay.
- Auto mode: we'd tell you to keep it on. A PreToolUse gate (hub v1.4) adds a physical check on top of auto mode for irreversible commands. It is built and verified with real processes and real OS hotkeys, but not yet tested inside a real auto-mode Claude Code / Codex session.

**Setup you'd do yourself**

- Codex: new hooks must be trusted via `/hooks` before they run. We don't bypass that.
- Claude Code: the `claude` CLI needs to be logged in (the desktop app login doesn't carry over).

**Privacy**

Runs locally, listens on 127.0.0.1 only, no network requests by default. Commands and code never leave your machine. If you opt in, we collect anonymous key-press counts and timings only (no commands, paths or project names), and you can see exactly what would be sent.

**Who we're looking for**

- 3+ agent sessions running at the same time on a normal day
- a Stream Deck, Ulanzi D200 or any macro pad (if you have none, you can still apply)
- willing to use it for 14 days and tell us what's wrong
