# CXT 宏键盘键位 v9

`hub_keys.json` 的顶层 `bindings` 是 v9 实测布局；键帽文字可能不同，按物理位置找键。第 1 排离手最远，第 5 排最近。只解释现有接口 0 的 USB 报文，不改写键盘。

从项目根目录启动：

```text
D:/conda/miniconda3/python.exe pc/hub.py --backend usb
```

## 5 排 × 4 列

| 位置 | 第 1 列 | 第 2 列 | 第 3 列 | 第 4 列 |
| --- | --- | --- | --- | --- |
| 第 1 排 | Claude / Codex，E | 微信，B | 飞书，Ctrl+Z | 浏览器，Space |
| 第 2 排 | 随层动作 1，G | 随层动作 2，Ctrl+F | 随层动作 3，H | 随层动作 4，单按 Alt |
| 第 3 排 | 上一个窗口 / 确认切窗，L | 复制，M | 粘贴，Ctrl+T | 浮窗 / 帮助，Ctrl+D |
| 第 4 排 | 打断 / Esc，单按 Ctrl | 截图，单按 Shift | 发送，U | 清空输入框，X |
| 第 5 排 | 批准，Tab | 拒绝，Ctrl+C | 语音，Ctrl+V | 留空，P（与旋钮 2 逆时针同码） |

修饰键 Alt、Ctrl、Shift 只有在 USB 直读模式下，单独按住不超过 600 毫秒并松开，才在松开时触发。出现其他普通键或修饰键就取消本次单按；例如 Ctrl+Z 的 Ctrl 前导报文不会额外打断任务。Raw Input 不触发这三颗单按。

语音仍采用现有 `voice_down` / `voice_up` 与配置的 tap/hold 模式，位置移到第 5 排第 3 颗。

## 跟随应用的第 2 排

| 层 | 第 1 颗 | 第 2 颗 | 第 3 颗 | 第 4 颗 |
| --- | --- | --- | --- | --- |
| Agent | 发“继续” | 发“跑测试” | 发“总结” | 到最新 |
| Agent 提问时 | 选项 1 | 选项 2 | 选项 3 | 选项 4 |
| 聊天 | 提示“这一步还没做” | 找人：微信 Ctrl+F / 飞书 Ctrl+K | 填“收到”，不发送 | 到最新 |
| 浏览器 | 后退 | 地址栏 | 关标签 | 刷新 |
| 视频 | 播放 / 暂停 | 上一条 | 下一条 | 全屏 |
| 默认 | 后退 | Tab | 关闭 Ctrl+W | 到底 |

Claude、Codex 桌面版使用 Agent 层；微信、飞书使用聊天层；Chrome、Edge、Firefox 使用浏览器层，视频标题或浏览器全屏时为视频层。前台稳定 300 毫秒才换层；切窗和会话/列表卡片打开期间冻结层。模板只在输入框为空且没有等待批准请求时发送。

`layers` 可以按层覆盖物理绑定，先查当前层再查全局：

```json
{"layers": {"chat": {"hid:0x0A": "ctx 1"}}}
```

## 四个旋钮

| 旋钮 | 顺时针 / 逆时针 HID | 转动 | 按下 HID | 按下 |
| --- | --- | --- | --- | --- |
| 1 窗口 | `hid:0x09` / `hid:0x16` | 在 Alt+Tab 中前后移动，第一步始终到上一个窗口 | `hid:0x0F` | 切窗中确认；其他时候回上一个窗口 |
| 2 会话 | `hid:0x15` / `hid:0x13` | 在会话卡片中选择，期间不动应用窗口 | `hid:0x14` | 卡片开着则打开所选会话，否则跳到下一个等你的会话 |
| 3 滚动 | `hid:0x2D` / `hid:0x2E` | 顺滑滚动前台应用所选栏，指针移到栏内并留在那里 | `hid:0x19` | 换下一栏，显示边框 1.2 秒；每个应用记住选择 |
| 4 列表 | `hid:0x30` / `hid:0x2F` | Agent 选问题/模板；浏览器换标签；视频快进/快退；默认上下键 | `hid:0x06` | 回车（列表开着时确认）；视频无列表时播放/暂停；聊天转动暂未实现 |

旋钮 1、2、4 使用软件段落：静止后先累计 2 个脉冲才走一步，随后每步默认分别需要 4、3、3 个脉冲。`config.json` 的 `knob_divider` 可覆盖后续门槛，如 `{"knob_divider":{"1":4,"2":3,"4":3}}`。反方向必须在 100 毫秒内连续出现两次才换向；250 毫秒无脉冲清空累加器；两步至少间隔 90 毫秒，多出的步数丢弃。旋钮 3 不分段，只做方向去抖。第 5 排第 4 颗单按只有一个 P 脉冲，达不到门槛，所以无效。

旋钮 1 在原窗口位置 0 与最后一个可切换窗口之间夹住，不绕圈。停转默认 700 毫秒松开 Alt，可用 `window_switch_release_ms` 调整；连续切换最长 5 秒强制释放。切换中按第 4 排第 1 颗取消，发 Esc 再松开 Alt；其他动作先松开 Alt。

## 浮窗与反馈

单屏平时是屏幕右侧中部 28 像素竖条，最多 6 个会话；双屏使用副屏右上角会话列表。状态字为批、问、完、错、跑、闲。浮窗穿透鼠标、不抢焦点。

第 3 排第 4 颗点按显示/隐藏竖条，按住超过 400 毫秒看当前层键位，松开收起；按住时转任何旋钮可在每块屏的右中、右上、右下、左中、左上、左下停靠点之间循环，松手保存。隐藏时的新批准请求仍显示 3 秒。

批准请求、提问、旋钮 2/4 选择、按住帮助时才展开卡片。会话卡片按等批准、提问、出错、完成未读、运行、空闲排序，同类最近活动在前；打开时顺序冻结，停手 2.5 秒自动收起。

反馈贴着竖条显示 0.9 秒：绿色成功，灰色没东西可做，红色失败。同一无效操作 3 秒内不重复提示；无效操作不向应用发按键。滚动、切窗、粘贴不显示反馈。

发送前检查 Agent 输入框，空时提示“输入框是空的”；打断使用 Stop 按钮，没有任务时提示“没有在跑的任务”；清空只允许可编辑文本框，否则提示“这里不是输入框”。没有待处理会话时提示“没有等你的会话”。

## 升级与历史配置

未修改的旧默认键位在应用准备配置时升级到 v9，并按原版本保存备份，例如 `hub_keys.json.bak-v8`。自定义绑定、hotkey 或 profile 不覆盖。现有 `hotkey` 和历史 `v2_emulation` 保留其原有含义；它们不采用上述默认物理键位。

Raw Input 只观察按键，无法阻止出厂快捷键漏进前台应用。Ctrl+D、Ctrl+C、Ctrl+V 会分别造成退出、打断、粘贴等原生效果；需要用户先把接口 0 更换为 WinUSB，再使用完整功能。软件不会改动未知厂商接口 `0xFF00`。
